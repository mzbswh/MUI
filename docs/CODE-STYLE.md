# 代码规范与目录边界

## 格式与检查入口

以仓库根目录的 `.editorconfig` 为准：UTF-8、LF、四个空格缩进、括号独占一行、禁止尾随空格、连续多个空行及结束大括号前的空行。控制流使用大括号，不把多条语句压在一行。简单转发或单行查询可以使用表达式成员；包含多个阶段的逻辑展开书写。

类型内按字段、构造方法、事件、属性/索引器、方法、嵌套类型分组。字段集中在前部，禁止与方法穿插；字段区与构造方法、不同成员组及各方法之间留一个空行。字段之间保持声明顺序，不为排版改变初始化执行顺序；带初始化器或条件编译的重排冲突必须人工审查。partial 文件各自遵守相同规则。

在仓库根目录执行：

```sh
python3 Tools~/format-code.py
python3 Tools~/format-code.py --check
python3 Tools~/format-code.py --braces
python3 Tools~/format-code.py --check --braces
```

检查覆盖 Runtime、Editor、Samples 和生成器的手写 C# 源码，排除 bin/obj。脚本使用 .NET 10 SDK 构建本地成员布局工具，先检查成员排列、分隔与多余空行，再检查空白缩进。连续空行检查使用 Roslyn 源码行和 token 范围，不改动字符串或注释内部的换行。工具直接引用 SDK 自带 Roslyn，不新增 NuGet 依赖。检查模式遇到空集合、布局冲突或格式差异会失败，但不替代编译、命名与架构审查。生成器输出共用同一套成员布局规则，保留模板原有参数和清单换行。

`--check --braces` 使用本地 Roslyn 语法工具检查控制流大括号，不加载各构建工程；连续的 `using (...) using (...) { ... }` 共享最终代码块。`--braces` 修复模式仍逐项目执行 IDE0011，首次使用前需恢复各构建项目依赖。涉及 Unity 的工作区应通过环境变量提供 `UnityManagedPath`、`UnityUIAssemblyPath` 和 `UnityTMPAssemblyPath`，与离线编译采用相同引用。工作区加载警告不能当作编译成功，格式修复之后仍需编译相关程序集。

## 命名与注释

- 类型、方法、属性、事件使用 PascalCase；参数、局部变量和私有字段使用 camelCase。避免仅表达实现过程的缩写，异步方法使用 Async 后缀。
- 注释统一中文，类型名和 API 名保留原文。公共生命周期、所有权和异步入口说明调用线程、清理责任、取消语义及失败行为；不要用注释逐行复述代码。
- 通常每个文件包含一个主要类型。与类型紧密相关且不公开使用的状态结构可以作为内部嵌套类型。
- partial 文件按职责命名，例如 `.Synchronous.cs`、`.Lifetime.cs`、`.Refresh.cs`。不按任意行数拆成 Part1/Part2，也不为了少几行创建无独立职责的包装层。

## 目录和依赖

- `Runtime/Core` 保存与渲染器无关的 UI 契约、绑定、通知和生命周期机制。
- `Runtime/Navigation`、`Runtime/ChildViews` 负责各自的界面实例关系。标准 UI 功能放在 `Runtime/Modules`，不能加入项目业务或基础设施。
- `Runtime/Rendering` 保存具体渲染适配。UGUI 的基础单控件放在 Elements；列表控件、虚拟化、模板和选择模型统一放在 Lists，避免同一功能散落在两个目录。
- 本地自动化会话与截图放在可选 `UGUI.Automation` 程序集；基础 `UGUI/Automation` 仅放控件输入适配契约和状态类型，不反向依赖自动化会话。
- `Editor` 只保存制作与诊断工具，不能成为 Runtime 的反向依赖；可选 TMP 适配与其编辑器扩展保持独立程序集。
- `Samples~` 保存项目接入示例，包括资源加载、语言目录读取和业务数据请求。示例不得成为 Runtime 的依赖。
- `Generators~` 保存生成器源码，`Analyzers` 保存发布产物，`Tools~` 保存开发工具。修改生成模板后需要重新发布生成器并验证产出。
- 移动 Unity 源文件时同步移动原 `.meta`，保留 GUID；新文件补齐元数据。修改路径后检查文档、程序集及构建输入。

详细依赖关系见 [代码架构](CODE-ARCHITECTURE.md)。目录移动不得改变公开命名空间或序列化字段，除非该 API 本身需要明确迁移。

## 实现约束

- Unity 对象使用 `== null` 或 `!= null` 检查，不使用 `?.`、`??` 判断原生对象是否存活。
- 纯同步路径不调用异步 API 探测完成状态，不阻塞任务，不在后台启动清理。混入异步能力时，在副作用前明确拒绝。
- 外部回调可能重入、关闭界面或使代际失效；回调之后、提交之前复核所属状态。清理继续处理其余持有项，并保留原始错误。
- UI 只归还自己持有的凭证；不实现资源后端、全局缓存预算、下载、存档、网络协议或业务事务。
- 不自动提交。未明确要求时不新增测试；按改动范围执行现有编译、格式检查和运行验收，并准确记录未验证部分。
- 验收 Unity 运行行为前，先核对目标项目路径和编辑器实例身份；只操作 MUI 验收实例，不以进程名批量退出、重启或关闭其他项目的编辑器。实例身份不明确时停止控制并重新核对。
